# Rule catalogue

183 rules, generated from `backend/app/analysis/rules/catalogue.py` by `make rules`. Do not edit this file by hand.

Every rule states the defect, the responsible owner, a single definite root-cause sentence and a single fix. The **Reference** column names the equivalent check in the market tools studied in [REFERENCE_TOOLS.md](REFERENCE_TOOLS.md).

**Rebuffer impact** — `direct`: the defect stops or starves playback on its own; `indirect`: it consumes headroom a player needs; `none`: it is a conformance or information finding.

#### `ADS-001` — Ad segments are delivered more slowly than content segments

**Root cause.** The host serving ad creatives responds more slowly than the content host, so the buffer drains across every ad break.

**Fix.** Serve ad creatives from an edge with the same delivery profile as the content.

#### `ADS-002` — Ad creative is encoded differently from the content rung

**Root cause.** The creative's resolution, profile or audio configuration differs from the rung it is spliced into, so the decoder reconfigures at the splice.

**Fix.** Transcode creatives to match the channel ladder before splicing.

#### `ADS-003` — Ad boundary carries no discontinuity tag on every rung

**Root cause.** The splice changes the encoding without EXT-X-DISCONTINUITY on each rung, so the player decodes new media with the previous configuration.

**Fix.** Emit EXT-X-DISCONTINUITY at every ad in and ad out on every rung.

#### `ADS-004` — Discontinuity counts diverge across rungs during or after an ad break

**Root cause.** The rungs leave the break with different discontinuity counts, so the Tizen player's shared counter freezes at the next switch.

**Fix.** Emit the same number of discontinuities on every rung across the break.

#### `ADS-005` — Delivered ad break duration differs from the declared duration

**Root cause.** The segments spliced into the break sum to a different duration than the cue declares, so the timeline shifts by the difference at every break.

**Fix.** Deliver ad content matching the declared break duration.

#### `ADS-006` — Ad segment duration exceeds the channel target duration

**Root cause.** A spliced segment is longer than the target duration the rung declares, so the player's refresh schedule misses it.

**Fix.** Segment ad creatives to the channel's segment duration.

#### `ADS-007` — In-band SCTE-35 cue has no matching playlist tag

**Root cause.** The transport stream signals a splice the playlist does not advertise, so the player enters the break with no notice.

**Fix.** Emit EXT-X-CUE-OUT or EXT-X-DATERANGE for every in-band splice.

#### `ADS-008` — Playlist cue has no matching in-band SCTE-35 signal

**Root cause.** The playlist advertises a splice the transport stream does not signal, so downstream consumers reading the bitstream see no break.

**Fix.** Carry SCTE-35 in-band for every playlist cue.

#### `ADS-009` — SCTE-35 break duration differs from the playlist cue duration

**Root cause.** The in-band signal and the manifest cue declare different break lengths, so the splice point and the return point disagree.

**Fix.** Derive the playlist cue duration from the SCTE-35 break duration.

#### `ADS-010` — EXT-X-CUE-OUT has no matching EXT-X-CUE-IN

**Root cause.** A break opened and did not close inside the window, so the player stays in ad state past the end of the break.

**Fix.** Emit EXT-X-CUE-IN at the end of every break.

#### `ADS-900` — Ad breaks are signalled consistently

**Root cause.** Every break opened and closed with matching cues, carried a discontinuity on every rung, and delivered its declared duration.

**Fix.** No action.

#### `AUD-001` — AAC configuration changed between segments

**Root cause.** The audio object type, sample rate or channel configuration changed from one segment to the next, so the device reconfigures the audio decoder mid-playback.

**Fix.** Keep the AAC encoder configuration constant for the life of the rendition.

#### `AUD-002` — Declared audio codec does not match the audio object type in the bitstream

**Root cause.** The manifest declares one AAC profile and the bitstream carries another, so the device selects a decoder profile the stream does not use.

**Fix.** Set the CODECS attribute to the audio object type the encoder produces.

#### `AUD-003` — Muxed segment carries no audio elementary stream

**Root cause.** The segment holds video with no audio, so playback runs silent for that duration on a muxed rung.

**Fix.** Mux audio into every segment of this rung.

#### `AUD-004` — Audio samples leave a gap on the timeline

**Root cause.** The audio track has fewer samples than its duration requires, so audio and video drift apart across the segment.

**Fix.** Emit continuous audio samples for the full segment duration.

#### `AUD-005` — Audio is silent for a measurable span

**Root cause.** The audio track carries no signal, so the channel plays without sound for that duration.

**Fix.** Restore audio on the contribution feed.

#### `AUD-006` — No audio segment covers a video segment's time range

**Root cause.** The demuxed audio rendition has no segment spanning the video's timeline position, so playback has no audio to present with that video.

**Fix.** Publish audio segments covering the same timeline as the video rungs.

#### `AUD-007` — Audio and video segment durations drift apart

**Root cause.** The accumulated audio duration diverges from the accumulated video duration, so the two tracks separate over the length of the window.

**Fix.** Segment audio and video on the same boundaries.

#### `AUD-008` — AC-3 or E-AC-3 parameters changed between segments

**Root cause.** The sample rate, channel mode or bitrate of the Dolby elementary stream changed mid-rendition, so the device reconfigures the audio decoder.

**Fix.** Keep the Dolby encoder configuration constant for the life of the rendition.

#### `AUD-009` — AC-4 frames do not align with the segment boundary

**Root cause.** AC-4 frames cross the segment boundary, so a player joining at that boundary starts inside an audio frame.

**Fix.** Align AC-4 frame boundaries with segment boundaries.

#### `AUD-900` — Audio configuration is constant and complete

**Root cause.** Every sampled segment carries audio with the same configuration as the segment before it.

**Fix.** No action.

#### `CDN-001` — Live media playlist carries a cache lifetime longer than half the target duration

**Root cause.** The edge holds the playlist past the point where a new segment exists, so a player refreshing on schedule receives a playlist without the segment it needs.

**Fix.** Set max-age on live media playlists to at most half the target duration.

#### `CDN-002` — Playlist response Age exceeds the target duration

**Root cause.** The edge serves a cached playlist older than one segment, so the segment list the player receives is behind the live edge.

**Fix.** Reduce the edge cache lifetime for live media playlists on this path.

#### `CDN-003` — CDN serves an older media sequence number than the origin

**Root cause.** The edge holds a stale playlist while the origin has already published newer segments, so the player runs out of media the origin is already serving.

**Fix.** Purge the stale edge object and lower the cache lifetime for this path.

#### `CDN-004` — Repeated fetches return media sequence windows that differ beyond the tolerance

**Root cause.** Edge nodes behind the same hostname hold different playlist versions, so which node a device reaches decides whether it stalls.

**Fix.** Synchronise the edge tier for this path or shorten the object lifetime so nodes converge.

#### `CDN-005` — Access-Control-Allow-Origin is absent

**Root cause.** The response carries no CORS header, so a browser-based player cannot read it.

**Fix.** Add Access-Control-Allow-Origin to playlist and segment responses.

#### `CDN-006` — Segment download time exceeds its playback duration

**Root cause.** A segment takes longer to arrive than it takes to play, so the player buffer drains while the segment is still in flight.

**Fix.** Raise delivery throughput for this rung at the edge, or lower the rung bitrate.

#### `CDN-007` — Measured delivery throughput is below the rung's declared bandwidth

**Root cause.** The edge delivers this rung more slowly than the rung's own bitrate, so sustained playback at this rung consumes buffer.

**Fix.** Raise delivery throughput for this rung at the edge.

#### `CDN-008` — A later fetch returns an older media sequence number than an earlier fetch

**Root cause.** One edge node serves a playlist version older than the one already delivered, which moves the player backwards on the timeline.

**Fix.** Purge the stale edge object and align the cache lifetime across the edge tier.

**Root cause.** The segments are encrypted and no matching key was supplied, so the video, audio and A/V rules had no readable payload to measure.

**Fix.** Supply clear KID and KEY pairs in the job options to include the bitstream checks.

#### `INFO-002` — ffprobe checks did not run

**Root cause.** ffprobe is not installed on the analyzer host, so the decode-error and quality detectors produced no measurement.

**Fix.** Install ffmpeg and ffprobe on the analyzer host.

#### `INFO-003` — Checks did not run on a geo-restricted resource

**Root cause.** The edge returned HTTP 403 for the analyzer's region, so the checks behind that resource produced no measurement.

**Fix.** Allow the analyzer host's address range, or supply a URL valid for it.

#### `INFO-004` — Layer attribution used header evidence rather than a layer comparison

**Root cause.** Only the playback URL was supplied, so each defect is attributed from its own layer and the response headers that prove it.

**Fix.** Supply the origin, CDN and SSAI URLs to pin each defect to the first layer it appears on.

#### `INFO-005` — Timestamp continuity was not checked across a boundary between non-consecutive segments

**Root cause.** The two segments sampled either side of this boundary are not consecutive, so there is no boundary between them to measure: a rung sampled every Nth segment never produces an adjacent pair, and a rung sampled in full misses one whenever a segment rolls out of the live window between two polls. The skipped segments carry the timestamps that join the two, and measuring across them reports their own duration as a gap.

**Fix.** Sample this rung in full, or shorten the poll interval, so consecutive segments are measured and the boundary can be checked.

#### `INFO-900` — No stream-side defect detected

**Root cause.** Every check that ran returned a clean measurement across the analysis window.

**Fix.** Escalate to the Samsung player and device investigation with this report attached.

**Root cause.** The edge publishes an AAAA record that does not accept a TCP connection, so a TV that prefers IPv6 spends its connection timeout before falling back to IPv4.

**Fix.** Flatten the CNAME chain to at most two hops.

**Root cause.** Resolution time adds to startup on every cold playback start.

**Fix.** Lower the record TTL pressure on the authoritative servers or move the zone to a faster provider.

#### `NET-900` — Hostname resolves and answers

**Fix.** No action.

#### `HTTP-001` — Redirect chain is longer than two hops

**Root cause.** Each hop adds a full request round trip before the first byte of media arrives.

**Fix.** Collapse the redirect chain so the playback URL reaches media in at most one hop.

#### `HTTP-002` — Redirect drops query parameters carried by the playback URL

**Root cause.** The redirect target omits parameters the origin requires, so the request that follows the redirect is rejected.

**Fix.** Preserve the full query string across the redirect.

#### `HTTP-003` — Redirect changes scheme or host

**Root cause.** The playback URL and the URL that serves media are on different hosts, so every child URI resolves against the post-redirect host.

**Fix.** No action; the analyzer resolves against the final URL.

#### `HTTP-004` — Request returns HTTP 403

**Root cause.** The edge refuses the request, which stops delivery for every device presenting the same token or originating in the same region.

**Fix.** Reissue the access token for this channel or correct the geo policy on the edge.

#### `HTTP-005` — Segment listed in the playlist returns HTTP 404

**Root cause.** The playlist advertises a segment the edge does not hold, so the player has nothing to decode for that position on the timeline.

**Fix.** Publish the segment to the edge before it is listed, or remove it from the playlist until it is present.

#### `HTTP-006` — Request returns HTTP 410

**Root cause.** The edge reports the resource permanently removed while the playlist still lists it.

**Fix.** Remove the resource from the playlist at the same time it is withdrawn from the edge.

#### `HTTP-007` — Request returns HTTP 429

**Root cause.** The edge rate-limits the client, so segment delivery stops until the limit window clears.

**Fix.** Raise the per-client rate limit for the TV Plus player profile on this edge.

#### `HTTP-008` — Request returns a 5xx status

**Root cause.** The edge or origin fails to produce the resource, so delivery stops for that position.

**Fix.** Investigate the edge error log for this path and restore the origin response.

#### `HTTP-009` — Playlist is served with a Content-Type that is not an HLS media type

**Root cause.** The response declares a type other than application/vnd.apple.mpegurl or application/x-mpegURL, which a strict client rejects before parsing.

**Fix.** Set Content-Type: application/vnd.apple.mpegurl on playlist responses.

#### `HTTP-010` — Response body is shorter than the declared Content-Length

**Root cause.** The edge closes the connection before sending the whole segment, so the player decodes a partial segment or discards it.

**Fix.** Investigate the edge connection reset for this path.

#### `HTTP-011` — Request does not complete within the request timeout

**Root cause.** The request exceeds the client timeout, so the player treats the resource as unavailable and retries.

**Fix.** Reduce time to first byte on this path at the edge.

#### `HTTP-012` — Time to first byte exceeds the budget

**Root cause.** The edge takes longer than the budget to start the response, which consumes buffer the player needs for the next segment.

**Fix.** Investigate edge cache misses and origin latency for this path.

#### `HTTP-013` — Connection reuse is disabled

**Root cause.** The edge closes the connection after each response, so every segment pays a fresh TCP and TLS handshake.

**Fix.** Enable HTTP keep-alive on the edge for this hostname.

#### `HTTP-014` — Segment is served with a Content-Encoding

**Root cause.** The segment body is transfer-encoded, which a legacy device decoder does not unwrap.

**Fix.** Serve segment bodies without Content-Encoding.

#### `HTTP-015` — Relative child URI resolves to a different host after the redirect

**Root cause.** The playlist uses relative URIs and the redirect moves the base to another host, so the children are fetched from a host that does not hold them.

**Fix.** Publish absolute child URIs, or stop redirecting the playlist across hosts.

#### `HTTP-900` — Every request returns a success status

**Root cause.** No playlist, init segment or media segment request returned a non-success status during the analysis window.

**Fix.** No action.

#### `SEQ-001` — Media sequence number advanced by a different amount than the segments that rolled off

**Root cause.** The declared sequence number and the segment list disagree about how far the window moved, so the player maps segments to the wrong positions.

**Fix.** Advance EXT-X-MEDIA-SEQUENCE by exactly the number of segments removed from the window.

#### `SEQ-002` — Media sequence number decreased

**Root cause.** A later playlist declares a lower sequence number than an earlier one, so the player is moved backwards on the timeline.

**Fix.** Serve monotonically increasing media sequence numbers from every edge node.

#### `SEQ-003` — Media sequence number jumped by more than the window length

**Root cause.** The window advanced past segments that were never published, so the media for those positions is absent from the timeline.

**Fix.** Publish every segment in sequence or hold the sequence number until media exists.

#### `SEQ-004` — Media sequence number advanced with an unchanged segment list

**Root cause.** The sequence number moved while the listed segments stayed identical, so the rung advertises progress it has not made.

**Fix.** Advance the sequence number only when the segment list changes.

#### `SEQ-005` — Media sequence number reset to a low value without EXT-X-ENDLIST

**Root cause.** The counter restarted mid-stream, so the player reads a position it has already played.

**Fix.** Keep the media sequence number monotonic for the life of the channel.

#### `SEQ-006` — Discontinuity sequence number decreased

**Root cause.** The discontinuity counter moved backwards, so the player's timeline mapping for this rung no longer matches the packager's.

**Fix.** Keep EXT-X-DISCONTINUITY-SEQUENCE monotonic.

#### `SEQ-007` — Discontinuity sequence number advanced by more than one between polls

**Root cause.** More than one discontinuity was consumed between two polls, so a discontinuity boundary passed without the player observing it.

**Fix.** Advance EXT-X-DISCONTINUITY-SEQUENCE one step at a time.

#### `SEQ-008` — Media sequence numbers across variants differ beyond the tolerated spread

**Root cause.** The rungs are published at different points on the timeline, so an ABR switch lands the player at a position the new rung has not reached.

**Fix.** Publish every rung of the ladder at the same live edge.

#### `SEQ-009` — Discontinuity sequence numbers differ across variants

**Root cause.** The Tizen player holds one discontinuity counter for the whole ladder, so rungs disagreeing on that counter freeze playback at the next switch.

**Fix.** Emit the same discontinuity count on every rung at the same timeline position.

#### `SEQ-010` — Variants list different segment counts or durations for the same media sequence number

**Root cause.** The same sequence number covers a different span of the timeline on different rungs, so an ABR switch changes the playback position.

**Fix.** Segment every rung on the same boundaries.

#### `SEQ-011` — Discontinuity tags sit at different positions across variants

**Root cause.** A discontinuity falls at a different timeline position on each rung, so a switch across the boundary reconfigures the decoder at a point the player did not prepare for.

**Fix.** Place discontinuity tags at identical timeline positions on every rung.

#### `SEQ-012` — Program date times differ across variants for the same position

**Root cause.** The rungs anchor the same media to different wall-clock times, so time-based alignment between video and audio resolves to different segments.

**Fix.** Emit the same program date time on every rendition for the same media.

#### `VID-001` — Segment does not start with a random access point

**Root cause.** The segment opens on a non-IDR slice, so a player joining or switching at this boundary has no picture to start decoding from.

**Fix.** Start every segment with an IDR picture for H.264 or an IRAP picture for HEVC.

#### `VID-002` — Segment carries no sequence or picture parameter set

**Root cause.** The parameter sets are absent from the segment and from the initialisation segment, so the decoder cannot be configured to decode it.

**Fix.** Emit SPS and PPS in every segment, or carry them in the initialisation segment.

#### `VID-003` — HEVC segment carries no video parameter set

**Root cause.** The VPS is absent, so an HEVC decoder cannot be configured for the segment.

**Fix.** Emit VPS, SPS and PPS in every HEVC segment.

#### `VID-004` — Sequence parameter set changed within a rung

**Root cause.** The coded picture configuration changed mid-rung, so the decoder reconfigures without an ABR switch to prepare it.

**Fix.** Keep the encoder configuration constant for the life of a rung.

#### `VID-005` — Resolution, profile or level changed at a discontinuity

**Root cause.** The media after the discontinuity is coded differently from the media before it, so the decoder reallocates at the splice.

**Fix.** Encode spliced content with the same resolution, profile and level as the channel.

#### `VID-006` — Rungs declare different reference frame counts

**Root cause.** The ladder's rungs commit the decoder to different decoded picture buffer sizes, so every ABR switch forces a buffer reallocation; the 2016 Tizen MFC decoder returns NOT_SUPPORT after such a reconfiguration.

**Fix.** Encode every rung with the same max_num_ref_frames.

#### `VID-007` — Keyframes are not aligned across rungs at the same media sequence number

**Root cause.** The rungs place their random access points at different timeline positions, so an ABR switch cannot resume decoding at the switch point.

**Fix.** Align the GOP structure across every rung of the ladder.

#### `VID-008` — Frame rate in the bitstream differs from the declared FRAME-RATE

**Root cause.** The manifest declares a frame rate the encoder did not produce, so the player drives the display at the wrong cadence.

**Fix.** Set FRAME-RATE to the value in the sequence parameter set VUI timing.

#### `VID-009` — Decoder reports errors on the segment

**Root cause.** Decoding the segment produces errors, so the picture breaks up or the decoder stops.

**Fix.** Re-encode the affected segments.

#### `VID-010` — Segment contains black frames

**Root cause.** The picture is black for a measurable span, so the channel shows no content for that duration.

**Fix.** Restore programme content on the contribution feed.

#### `VID-011` — Segment contains frozen frames

**Root cause.** The picture does not change for a measurable span, so the channel shows a still image where motion is expected.

**Fix.** Restore the contribution feed for this channel.

#### `VID-012` — Rung is interlaced

**Root cause.** The rung codes fields rather than frames, so the device deinterlaces before display.

**Fix.** Encode the ladder progressive.

#### `VID-900` — Video bitstream is conformant

**Root cause.** Every sampled segment starts on a random access point, carries its parameter sets, and keeps one coded configuration across the rung.

**Fix.** No action.
